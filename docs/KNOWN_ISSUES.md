# 已知问题与限制清单

## A. 环境适配（已解决，但需知晓）

1. **PostgreSQL 为便携版且需手动启动**：无管理员权限。机器重启后需按 RUNBOOK 启动 postgres 进程，否则后端报连接拒绝。
2. **SQLAlchemy 使用 1.4 纯 Python 模式**：2.x 的 C 扩展被系统应用控制策略拦截。性能略低，但对本规模无影响。
3. **前端端口为 5174**：5173 被本机其他项目（java-learning）占用，已固定 5174 并同步 CORS。
4. **数据库不使用 Alembic 迁移**：采用 `create_all` + 幂等 seed。新增字段/表时需注意旧库不会自动变更结构。
5. **本机禁止执行新生成的二进制**：应用控制策略（WinError 4551）同时拦截生成的 exe 与加载新编译的 DLL，因此 C 代码在线运行不能采用「gcc 编译后执行」路径。

## B. 功能限制（当前设计如此，非缺陷）

1. **C 代码运行是受限子集解释器**：支持变量、数组、指针、函数、分支、循环、`printf`/`strlen`/`sizeof` 等教学常用语法；不支持结构体、文件 IO、多线程、预处理宏展开等完整 C11 特性。遇到不支持语法会明确提示。gcc 只做 `C11 -fsyntax-only` 校验。
2. **题目未经编译器自动验证**：题库答案按 C11 语义人工核对；由于本机无法执行二进制，未做编译运行比对。生产环境应接入容器沙箱后增加自动校验。
3. **AI 助手默认使用内置规则引擎**：未配置密钥时能力有限（概念检索、代码模式匹配、错误关键词解读）。配置密钥后自动切换为大模型。密钥只存服务端，接口不回传。
4. **AI 出题的本地回退质量有限**：未配置大模型密钥时，AI 出题走内置模板生成器（基于知识点的概念、常见错误生成判断题/填空/辨析题），能通过格式与答案校验但题目质量不如大模型。配置密钥后自动切换为大模型生成。题库扩充的 32 道题（含 LeetCode 风格编程题）为人工编写并核对。
5. **连续学习天数（streak_days）恒为 0**：字段已存在，尚未实现按日登录更新逻辑。
6. **编程题判分**：填空题/编程题按归一化字符串比对或人工评价，未接入自动化测试用例判题。题库已包含 8 道 LeetCode 风格编程题（两数之和、有效括号、最大子数组和、三数之和等），答案为参考要点，采用测试用例或人工评价。

## C. 待改进（非阻塞）

1. ECharts 与代码高亮使首屏 JS 包约 1.47MB，可通过动态 import 拆分优化。
2. 未做像素级视觉还原：需求提到的两张参考图未随消息附上，当前按文字规范实现（深墨绿/黑绿、荧光绿、细边框半透明面板、网格光效、工业控制台布局）。
3. 微交互以 CSS transition 为主（Snap Grid、Ripple、进度动画、关卡错峰出现等），Framer Motion 级进阶动画留待后续打磨。
4. 考试题型分值可在配置页自定义，但若用户设置的题型在题库中题量不足，接口返回 409 并列出缺口。与练习不同，考试**不会自动补题**——这是为了保证考试题目在组卷前已全部经过校验，避免考试过程中动态生成影响公平性与保密性。
5. 练习自动补足题目时，若用户勾选了多种题型，只会按第一个勾选题型 + 第一个勾选难度生成补足题；如需精确控制补足题型，请先使用练习配置页的「AI 出题」手动补充。
